## 开发任务：途友·活动报名/取消报名功能

### 一、功能概述

实现活动报名和取消报名的完整闭环，涉及**活动详情页**和**活动列表页**两个场景的报名状态同步更新。


### 二、接口说明

#### 2.1 报名/取消报名接口（切换接口）

**接口地址**：`POST /activities/{id}/signup`

**请求参数**：

| 参数 | 类型   | 必填 | 说明               |
| ---- | ------ | ---- | ------------------ |
| `id` | string | ✅    | 活动ID（路径参数） |

**响应体**：

```typescript
interface SignupResponse {
  code: number
  message: string
  data: {
    isJoined: boolean      // true=已报名，false=未报名（操作后的状态）
    currentPeople: number  // 操作后的最新报名人数
  }
}
```

**核心逻辑**：
- 接口是**切换型**的：当前 `joined=true` 时调用 → 取消报名；`joined=false` 时调用 → 报名
- 后端根据当前用户的报名状态自动判断是"报名"还是"取消报名"

**后端校验**（需前端配合提示）：

| 校验项            | 错误码 | 说明                               |
| ----------------- | ------ | ---------------------------------- |
| 活动不存在/已删除 | 404    | 活动已被删除或不存在               |
| 活动已满员        | 2001   | 报名人数已达上限                   |
| 不在报名时间内    | 2001   | 当前时间早于报名开始或晚于报名截止 |
| 活动已结束        | 2001   | 活动状态为已结束                   |

#### 3.3 按钮状态与文案映射

| 条件                                           | 按钮文案         | 可点击 | 颜色        | 点击行为       |
| ---------------------------------------------- | ---------------- | ------ | ----------- | -------------- |
| `joined=false` 且 `activityStatus='报名中'`    | 立即报名         | ✅      | 主色        | 弹出报名确认框 |
| `joined=true` 且 `activityStatus='报名中'`     | 取消报名         | ✅      | 警告色/灰色 | 弹出取消确认框 |
| `activityStatus='进行中'`                      | 已开始，无法报名 | ❌      | 灰色        | 无反应         |
| `activityStatus='已结束'`                      | 已结束           | ❌      | 灰色        | 无反应         |
| `currentPeople >= maxPeople` 且 `joined=false` | 已满员           | ❌      | 灰色        | 无反应         |


#### 3.4 成员列表更新逻辑

报名/取消报名后，`members` 列表需要同步更新：

```typescript
// 方式1：从接口返回更新（推荐，最准确）
// 由于接口不返回 members 列表，需要本地维护更新

const updateLocalState = (newJoined: boolean, newCurrentPeople: number) => {
  const userInfo = Taro.getStorageSync('userInfo')
  
  // 更新 Redux 中的活动数据
  dispatch(updateActivitySignup({ 
    activityId: id, 
    joined: newJoined, 
    currentPeople: newCurrentPeople 
  }))
  
  // 同时更新 members 列表
  if (newJoined) {
    // 报名：添加当前用户到 members
    dispatch(addActivityMember({ 
      activityId: id, 
      member: { 
        id: userInfo.id, 
        nickname: userInfo.nickname, 
        avatar: userInfo.avatar 
      } 
    }))
  } else {
    // 取消报名：从 members 中移除当前用户
    dispatch(removeActivityMember({ 
      activityId: id, 
      memberId: userInfo.id 
    }))
  }
}
```

### 四、活动列表页报名状态同步

#### 4.1 问题场景

用户从详情页报名后返回列表页，列表页的 `joined` 和 `currentPeople` 需要同步更新。

#### 4.2 解决方案

**方案一：页面显示时刷新列表（推荐）**

```typescript
// 在活动列表页使用 useDidShow
import { useDidShow } from '@tarojs/taro'

const ActivityList = () => {
  const dispatch = useDispatch()
  const { page, category, size } = useSelector(state => state.activity.filters)

  useDidShow(() => {
    // 从详情页返回时刷新列表（不重置页码，保留当前筛选条件）
    dispatch(fetchActivities({ page, category, size }))
  })
}
```

**方案二：Redux 全局状态同步**

报名成功后，通过 Redux 更新对应活动的状态（适用于详情页报名后列表页无需刷新即可更新）：

```typescript
// store/modules/activity.ts
updateActivitySignup: (state, action: PayloadAction<{ 
  activityId: string, 
  joined: boolean, 
  currentPeople: number 
}>) => {
  const { activityId, joined, currentPeople } = action.payload
  
  // 更新列表中的活动
  const activity = state.activityList.find(a => a.id === activityId)
  if (activity) {
    activity.joined = joined
    activity.currentPeople = currentPeople
  }
  
  // 更新当前详情页活动
  if (state.currentActivity?.id === activityId) {
    state.currentActivity.joined = joined
    state.currentActivity.currentPeople = currentPeople
  }
}
```

### 五、错误码处理

根据接口文档，后端可能返回以下错误：

| 错误场景          | 错误码 | 前端处理                           |
| ----------------- | ------ | ---------------------------------- |
| 活动不存在/已删除 | 404    | Toast 提示"活动不存在"，返回列表页 |
| 活动已满员        | 2001   | Toast 提示"报名人数已满"           |
| 不在报名时间内    | 2001   | Toast 提示"不在报名时间内"         |
| 活动已结束        | 2001   | Toast 提示"活动已结束"             |
| 其他错误          | -      | Toast 提示接口返回的 message       |

```typescript
try {
  await dispatch(toggleSignup(id)).unwrap()
} catch (error: any) {
  // 根据错误码或错误信息给出友好提示
  const message = error?.message || '操作失败，请重试'
  
  // 错误码映射
  const errorMap = {
    '404': '活动不存在或已删除',
    '2001': '操作失败，请确认活动状态'
  }
  
  const friendlyMsg = errorMap[error?.code] || message
  Taro.showToast({ title: friendlyMsg, icon: 'error' })
}
```


### 六、边界情况处理

| 场景               | 处理方式                                           |
| ------------------ | -------------------------------------------------- |
| 网络异常           | Toast 提示"操作失败，请重试"，状态回滚             |
| 重复点击           | 设置 `submitting` 状态，按钮 loading，防止重复提交 |
| 已满员时报名       | 按钮置灰显示"已满员"，不可点击                     |
| 非报名中状态       | 按钮置灰，不可点击                                 |
| 未登录用户点击报名 | 跳转登录页（或弹出登录引导）                       |
| 活动已结束         | 按钮置灰显示"已结束"                               |
| 同时报名人数超限   | 后端返回错误码 2001，Toast 提示"报名人数已满"      |

### 九、Store 层实现（仅参考，实际以原有实现代码习惯为基础）

```typescript
// store/modules/activity.ts

// 报名/取消报名 Action
export const toggleSignup = createAsyncThunk(
  'activity/toggleSignup',
  async (activityId: string, { rejectWithValue }) => {
    try {
      const res = await signupActivity(activityId)
      if (res.code === 0) {
        return { activityId, ...res.data }
      }
      return rejectWithValue({ code: res.code, message: res.message })
    } catch (error: any) {
      return rejectWithValue({ code: -1, message: error.message })
    }
  }
)

// Reducer
extraReducers: (builder) => {
  builder
    .addCase(toggleSignup.pending, (state) => {
      state.loading = true
    })
    .addCase(toggleSignup.fulfilled, (state, action) => {
      const { activityId, isJoined, currentPeople } = action.payload
      
      // 更新列表页中的活动
      const activity = state.activityList.find(a => a.id === activityId)
      if (activity) {
        activity.joined = isJoined
        activity.currentPeople = currentPeople
      }
      
      // 更新详情页中的活动
      if (state.currentActivity?.id === activityId) {
        state.currentActivity.joined = isJoined
        state.currentActivity.currentPeople = currentPeople
      }
      
      state.loading = false
    })
    .addCase(toggleSignup.rejected, (state) => {
      state.loading = false
    })
}
```
