> 写给项目同学看的一份大白话报告。不需要懂全部技术细节也能看懂：这次改了什么、为什么改、改完有什么好处、以后怎么跑。

## 一、概述：这次到底做了什么？

简单说：**在不改任何页面功能、不影响现有使用的前提下，把整个项目的"地基"重铺了一遍。**

分四轮做完，外加一轮死代码清理：

| 轮次 | 干的事 | 通俗解释 |
|---|---|---|
| 第 1 轮：数据契约层 | 统一响应格式、请求封装、API 层、类型层 | 定一个"全国统一标准"，以后后端返回什么、前端怎么接，都按同一个规矩来 |
| 中间穿插：死代码清理 | 删除没人引用的文件和代码 | 把房间里堆了几年的旧纸箱全扔了，只留有用的 |
| 第 2 轮：store（Redux） | 10 个状态模块统一写法 | 原来每个模块各写各的"样板代码"，现在全仓库一套模板 |
| 第 3 轮：组件 | 28 个通用组件全部规范化 | 每个组件要什么参数、什么类型，写得清清楚楚 |
| 第 4 轮：页面 | 26 个页面全部接入新规范 | 页面不再自己拼请求、自己跳路由，全部走统一入口 |

**最重要的承诺：功能零回归。** 登录、注册、首页瀑布流、详情、评论、点赞、收藏、关注、报名、发布、搜索、消息——所有交互行为和之前一模一样，只是代码更干净了。

## 三、架构梳理（大白话版）

### 3.1 数据是怎么流动的？

以前大家各写各的：有的页面直接 `Taro.request`，有的 import 底层 `get`，跳转有的用 `Taro.navigateTo` 有的自己拼路径。

现在全仓只有一条路：

```
页面/组件
   │  （要数据？找 store；要跳转？找 router）
   ▼
store（Redux，可选）
   │
   ▼
apis（领域 API 薄封装，11 个领域）
   │
   ▼
utils/request（统一请求层：加 token、判成功码、解包、401 处理）
   │
   ├── Mock 模式 → 本地内存假数据
   └── 真接口模式 → 后端服务器
```

一句话总结规矩：

> **页面只调 apis，不碰 request；跳转只调 router，不碰 Taro。**
> 这样以后要换后端、改路由规则、加统一逻辑（比如登录过期处理），都只需要改一个地方。

### 3.2 什么是"统一响应信封"？

后端返回的数据统一长这样：

```ts
{ code: 0, message: "成功", data: { ...真正的数据... } }
```

- `code`：业务状态码，`0` 或 `200` 都算成功；
- `message`：提示语，失败时可以直接弹给用户看；
- `data`：真正要的数据。

以前每个 thunk 都要写一遍 `if (res.code === 0 || res.code === 200) { return res.data } else { throw ... }`，重复几百遍。

### 3.3 `apiGet` 等 5 个快捷函数是干嘛的？

请求层封装了 5 个快捷函数：`apiGet / apiPost / apiPut / apiDelete / apiPatch`。

它们 = "发请求" + "自动拆信封"，一步到位，直接返回 `data`：

```ts
// 以前（每个 thunk 都写一遍样板）
const res = await get('/notes', params)
if (res.code === 0 || res.code === 200) return res.data
throw new Error(res.message)

// 现在（一行搞定）
export function getNotes(params: NoteQueryParams) {
  return apiGet('/notes', params)   // 返回的就是拆好的 data
}
```

## 四、每一层具体干了什么

### 4.1 请求层（`src/utils/request.ts`）

- **统一解包**：新增 `unwrap()` 和 `ApiError`。成功就返回数据，失败就抛出一个带 `message` 的错误，`message` 可以直接 Toast 弹给用户。
- **自动带 token**：每个请求自动加 `Authorization: Bearer <token>`，不用业务层管。
- **401 统一处理**：登录过期/没登录时，只在这一个文件里清 token + Toast + 跳登录页。**业务代码再也不用判断"是不是 401"。**
- **可取消请求**：支持 `AbortSignal`，防止快速切换分类时旧请求晚回来把新数据覆盖掉（竞态问题）。
- **Mock 降级**：开着 Mock 就走本地；关了 Mock 发真实请求，开发/测试环境失败会自动回退 Mock，**生产环境不允许降级**（宁可报错也不能给用户看假数据）。

### 4.2 API 层（`src/apis/`，11 个领域）

- 每个领域一个文件：`user / note / guide / activity / home / profile / tag / upload / message / comment / search`。
- 函数命名统一**不带 API 后缀**：`getNotes`、`createNote`、`toggleNoteLike`……（以前叫 `loginAPI` 这种，现在全改了）。
- 每个函数几行代码，注释标明后端路径，不写业务逻辑。

### 4.3 类型层（`src/types/`）

- 所有业务类型集中管理：实体（`entity.ts`）、协议（`api.ts`，信封/分页/枚举）、上传（`upload.ts`）。
- 消灭了全部 `any`；确实缺类型的地方用 `unknown` + 收窄，或加注释的最小局部断言。

### 4.4 状态管理（`src/store/modules/`，10 个模块）

| 模块 | 管什么 |
|---|---|
| `user` | 登录态、用户信息、登录/注册/登出 |
| `home` | 首页轮播、笔记瀑布流（分页/分类/下拉刷新/滚动位置记忆） |
| `note` | 笔记列表与详情、点赞/收藏 |
| `guide` | 攻略列表 |
| `activity` | 活动列表、Banner、报名 |
| `profile` | 个人主页资料、自己的作品 |
| `comment` | 评论树 |
| `message` | 互动/系统消息、未读数 |
| `tag` | 标签 |
| `upload` | 图片上传任务状态 |

主要变化：

- **thunk 一行化**：apis 已经拆好信封了，取数 thunk 直接 `return await getXxx(params)`，失败自动抛错。
- **乐观更新**：点赞/收藏/关注时，点下去界面立刻翻转（不等服务器）；失败了自动回滚；服务器返回后再用真实值校准。**体验快，数据又准。**
- **AbortError 不回滚**：快速切换列表时被主动取消的请求，不做任何回滚处理，避免误清数据。

### 4.5 组件（`src/components/`，28 个单元）

- 每个组件 props 都有明确类型（`interface XxxProps`），不再有"这个组件到底传啥"的疑问。
- 回调统一 `onXxx`（`onClick`、`onSignup`），内部处理函数统一 `handleXxx`。
- 组件里跳转一律走 `@/router` 包装函数，不再出现 `Taro.navigateTo`。
- 唯一例外是 `PostWaterfall`（首页瀑布流，原 NoteList 改名）内部自带点赞——这是有意保留的性能设计，文件里有注释说明。
- 样式全部 `index.less`，`index.css` 已全部删除。

### 4.6 页面（`src/pages/`，26 个页面目录）

- 三态齐全：loading（转圈/骨架屏）、空态（空文案）、错误态（错误信息 + 重试）。
- 新增账号管理子页路由键：`CHANGE_PASSWORD`（改密）、`CHANGE_PHONE`（换绑手机）、`CANCEL_ACCOUNT`（注销账号）。
- 页面内跳转一律 `routerNavigateTo('NOTE_DETAIL', { id: 123 })` 这种写法，第二参自动拼 query。

### 4.7 Mock 系统（`src/mock/`，14 个文件）

- 路由键格式：`"GET /api/v1/notes/:id"` 这种"方法 + 路径"。
- **有状态 Mock**（这次升级的重点）：点赞后数字真的翻转、发布后列表里真能看到、评论后详情页真有——不是每次返回写死的假数据。
- 模拟 300–800ms 延迟，让 loading 效果能被看到（不然转圈一闪而过，开发时发现不了加载态的样式问题）。

## 六、重点：以后后端好了，怎么切真接口？

**只需要改一个开关，业务代码一行都不用动。**

打开 `.env.development`，把：

```env
TARO_APP_USE_MOCK=true
```

改成：

```env
TARO_APP_USE_MOCK=false
```

保存重启 `pnpm dev:h5` 即可。

- `.env.test` 和 `.env.production` 里这个值**已经是 `false`**，测试/生产环境本来就走真实接口。
- 开发环境刚切真接口时，如果后端某个接口还没写完会请求失败——这时会自动降级回 Mock，页面不会白屏；等后端全部就绪就彻底不用 Mock 了。
- **生产环境永远不降级**，请求失败就是失败，不会拿假数据糊弄线上用户。
