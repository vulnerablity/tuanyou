# 团游前端《代码规范》——全仓重构共享契约

> 本文档是本次"从头到尾"重构的唯一契约来源。所有分片（数据层 / store / 组件 / 页面）必须
> 严格按本文档执行；与本文档冲突的写法视为违规。文中所有路径均为项目根 `D:\DOCSTUDY\tuyou-web` 下相对路径。

## 0. 目标与验收红线

- **功能零回归**：27 个页面全部可用，登录/注册/改密/首页瀑布流/详情/评论/点赞/收藏/关注/报名/发布/搜索/消息等交互行为不变。
- **Mock 可插拔**：页面与组件只通过 `src/apis` 取数；切换环境变量 `TARO_APP_USE_MOCK` 即可无缝切换真后端，业务代码零改动。
- **规范一致**：分层清晰、命名统一、类型齐全、同一能力只实现一次。
- **每轮结束后 `pnpm exec tsc --noEmit` 必须全绿**（各分片负责人自查 + 总协调复核）。禁止留下编译错误进入下一轮。

## 1. 分层架构（依赖方向：上层依赖下层，禁止反向）

```
src/
├── app.tsx / app.config.ts / app.less     应用壳（配置/全局样式/全局副作用）
├── assets/                                静态资源（图片/字体）
├── types/                                 共享类型（entity 实体 / api 协议域 / upload 专项 / index barrel）
├── utils/                                 基础工具：request(请求+Mock切换)、token、sse、时间格式化等
├── router/                                路由常量 + 导航包装（唯一允许直调 Taro 导航 API 的地方）
├── apis/                                  领域 API 薄封装（业务层唯一取数入口）
├── mock/                                  各领域 Mock 路由与数据（仅 Mock 模式生效）
├── store/                                 Redux：modules/<领域>.ts + index.ts 组装
├── hooks/                                 共享 React Hooks（跨组件/页面复用）
├── components/                            通用组件（目录式：components/<Name>/index.tsx + index.less）
└── pages/                                 页面（pages/<Page>/index.tsx + index.less + components/ 局部组件）
```

数据流：`页面/组件 → store(可选) → apis → request → (Mock 或真实后端)`。
**页面与组件禁止直接 `import { request, get, post } from '@/utils/request'`**，一律走 `src/apis`。

## 2. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 页面/组件目录 | PascalCase | `pages/Home/index.tsx`、`components/ActivityCard/` |
| 非组件文件 | kebab-case | `utils/formatMessageTime.ts` |
| 组件 | PascalCase，默认导出 | `export default function ActivityCard()` |
| 函数/变量 | camelCase | `getCategoryParam`、`feedLoading` |
| 常量 | SCREAMING_SNAKE | `CATEGORY_MAP`、`TOKEN_KEY`、`PUBLIC_ROUTES` |
| 类型/接口 | PascalCase，不用 I 前缀 | `interface PostProps`、`type UserRole` |
| API 函数 | `动词 + 领域名词`，**统一不带 API 后缀** | `getNotes`、`getNoteDetail`、`createNote`、`toggleNoteLike`、`deleteNote` |
| Store thunk | `fetchXxx`（取数）/`toggleXxx`（开关）/动词 | `fetchNotes`、`toggleLike` |
| 组件回调 props | `onXxx` | `onClick`、`onSignup`、`onLoadMore` |
| 布尔 props / 状态字段 | `isXxx` / `showXxx` / `hasXxx` | `isLiked`、`hasMore`、`loading` |
| CSS 类名 | kebab-case，语义化 | `activity-card`、`progress-bar` |
| 路由键 | SCREAMING_SNAKE | `NOTE_DETAIL`、`ACTIVITY_LIST` |

命名一致性硬要求：**同一事物全仓只用一个名字**（如"关注"统一 `toggleFollow`，不出现 `followUser/toggleFollowUser` 并存）。

## 3. 类型规范

- 所有业务类型集中在 `src/types`：`entity.ts`（业务实体）、`api.ts`（协议域：枚举/分页/DTO/信封）、`upload.ts`、`index.ts`（barrel 聚合，调用方 `import type { X } from '@/types'`）。
- 统一响应信封：`ApiResponse<T> { code: number; message: string; data: T }`；成功码 `code ∈ {0, 200}`。
- 分页结果：`PageResult<T> { list: T[]; total: number; page: number; size: number; total_page?: number }`。
- **消灭 `any`**（改前基线 242 处）：优先精确类型；组件库/Taro 缺类型处用 `unknown` + 收窄，或最小范围局部断言并加注释说明原因。禁止 `as any` 随手甩。
- 请求参数类型定义在 `apis` 层或 `types/api.ts`，禁止调用方散落匿名对象。
- 类型导入统一 `import type { ... }`（编译期类型勿进运行时 import）。

## 4. 请求层契约（src/utils/request.ts）

保留现有全部能力，只做类型化与契约化：

1. `TARO_APP_USE_MOCK=true` → 直接走 Mock；`false` → 真实请求，失败时**仅开发/测试环境**降级 Mock（生产禁止降级）。
2. Bearer token 自动注入；401（HTTP 或业务码）统一清 token + Toast + 跳登录（仅本文件内直调 `Taro.redirectTo` 登录页，业务层不得重复处理 401）。
3. `AbortSignal` 支持保持（防重复请求/过期响应丢弃）。
4. `upload` / `uploadBatch` 逻辑与签名保持（Mock 走 `mockFn` 分支）。
5. **新增统一解包能力**（本轮核心契约）：
   - 导出 `unwrap<T>(res: ApiResponse<T>): T`——`code ∈ {0,200}` 返回 `data`，否则 `throw new ApiError(code, message)`。
   - 导出便捷封装 `apiGet<T>/apiPost<T>/apiPut<T>/apiDelete<T>/apiPatch<T>`：内部 = `request + unwrap`，**返回解包后的 data**（`Promise<T>`）。
   - 底层 `request<T>` / `get` / `post` / `put` / `del` 继续导出（上传 `mockFn`、个别需要信封的场景使用），但业务层默认走 `apiXxx`。
   - `ApiError extends Error { code: number }`，`message` 可直接展示。
6. 消灭 `data?: any / header?: any` 等 any；Mock 每请求的 `console.log('[Mock] 路由查找:'...)` 等调试噪音删除（保留异常路径的错误日志）。
7. `__fromMock` 标记保留在信封上（仅活动 store 现有场景使用，见 §7 备注）；解包后业务层默认不再感知。

## 5. API 层契约（src/apis/*.ts）

- 每领域一个文件（`user/note/guide/activity/home/profile/tag/upload/message/comment/search`），与 mock 领域一一对应。
- 每个函数：**返回 `Promise<解包后的 data>`**，参数类型化，一行或几行薄封装，注释注明后端路径：
  ```ts
  /** GET /notes - 笔记列表（瀑布流） */
  export function getNotes(params: NoteQueryParams): Promise<PageResult<Post>> {
    return apiGet('/notes', params)
  }
  ```
- 函数命名按 §2；`toggle` 类操作统一返回后端校准值结构（如 `{ isLiked, likeCount }`），由 store/页面按类型消费。
- 带 `signal` 参数的函数签名统一为 `(id, signal?)`。
- 领域请求参数类型（`NoteQueryParams` 等）定义在此处或 `types/api.ts`，集中管理。
- **禁止在 apis 层做任何业务逻辑**（合并字段/判空等一律放页面或 store）。

## 6. Mock 契约

- 路由键格式 `"METHOD /api/v1/path"`，支持 `:param` 参数化（request.ts 匹配器已支持）。
- 处理器统一签名：`(data?: Record<string, unknown>, url?: string) => ApiResponse<unknown>`；模块导出 `xxxMockRoutes`，`src/mock/index.ts` 聚合（**保持聚合结构与导出对象不变**）。
- 工具函数（`src/mock/utils.ts`）：`successResponse/errorResponse/createPageResponse/randomInt/randomItem/randomDate` 保留，统一导出。
- **有状态 Mock（本轮硬要求）**：点赞/收藏/评论/关注/报名/发布/删除等交互必须真实修改模块级内存数据——发布后列表/详情可见，点赞后数字与状态翻转，再次请求保持。禁止每次返回写死的假状态。
- 分页/筛选/排序：列表接口必须支持 `page/size` 与领域筛选参数（分类/排序/类型/关键词等），返回 `total_page`；至少保留一个可返回空列表的路径（供空态验证）。
- 模拟延迟保留（现有 300–800ms），让 loading 态可见。
- 删除 Mock 文件中的 `console.log` 调试噪音；`mockNoteDetailPost` 等导出对象若与实际类型不一致，统一用 `satisfies`/显式类型收敛为真实 `Post`/`Comment` 类型（消灭 `Record<string, any>`）。
- `.env.development` 设置 `TARO_APP_USE_MOCK=true`（用户现阶段无后端，Mock 优先）；`.env.test`/`.env.production` 保持 `false` 并注释说明"后端就绪后把 development 改为 false 即切真接口"。

## 7. Store 契约（src/store/*.ts）

- 每领域一个 slice，`index.ts` 组装（reducer 键名保持现状：user/note/guide/activity/home/profile/tag/upload/message/comment）。
- **Thunk 统一写法（本轮核心）**——apis 已解包，不再手写 `if (res.code === 0 || ...)` 样板：
  ```ts
  export const fetchNotes = createAsyncThunk('note/fetchNotes', async (params: NoteQueryParams) => {
    return await getNotes(params)   // 失败自动 reject，action.error 携带信息
  })
  ```
  - rejected 处理器统一读 `action.error.message ?? '网络错误'`；AbortError 场景判 `action.error.name === 'AbortError'` 直接返回不回滚。
  - 需要"网络错误/业务错误"区别的场景用 `rejectWithValue`（仅限确有需要的 thunk，如登录失败提示语）。
- 状态字段命名统一：`loading / error / list 或按语义（notes/feed/...）/ total / page / size / hasMore / totalPage`；**保持现有导出名与 state 字段名不变**（页面按现状消费，禁止改名引发连锁修改）。
- 乐观更新（点赞/收藏/关注）：三态齐全——pending 立即翻转、rejected 回滚（AbortError 除外）、fulfilled 用后端真实值校准。各领域实现必须与 note.ts 现有模式一致。
- 领域 selector 统一导出（如 `selectFeed`），页面优先用 selector。
- 登录/注册成功后 `setToken` 由 thunk 内处理（现状保留）；`logout` reducer 内 `clearToken()`（现状保留）。
- 备注：`activity` store 现有对响应 `__fromMock` 的使用可保留（走底层 request 信封）；其余领域一律用解包 API。

## 8. 组件契约（src/components/*）

- 目录式组织；props 一律显式 `interface XxxProps`，**禁止未类型化 props / 隐式 any**。
- 函数组件（允许 FC 或不写 FC 皆可，全仓统一一种：**不写 React.FC**，直接函数 + Props 参数）。
- 事件回调 props 命名 `onXxx`；组件内部事件处理函数 `handleXxx`。
- 静态样式全部进 `index.less`；内联 `style={{...}}` 仅限动态值（进度条宽度、动态颜色等）。
- 列表渲染必须 `key`：优先稳定业务 id，静态常量列表（分类/排序 Tab）可用 index 并注释。
- 禁止渲染中 `setState`（在 render 内调用）；副作用进 `useEffect`；防抖/竞态用现有 hooks。
- 组件不自发发请求（取数由页面/store 驱动）；**例外保留**：`PostWaterfall` 内部点赞（乐观 UI + 防重复，现状设计，保留并在文件头注释说明）。
- 导航一律走 `src/router` 包装函数，禁止组件内 `Taro.navigateTo/redirectTo/switchTab/reLaunch` 直调。
- 样式文件统一 `index.less`；**不再 import 任何 `index.css`**（死 css 由清理分片统一删除）。
- `AuthRoute.tsx`：`withAuth / useAuthGuard / useAuthCheck / requireAuth` 能力与导出名保持，内部 any 清理、逻辑保留。

## 9. 页面契约（src/pages/*）

- 页面注册 `app.config.ts` **保持现状**（禁止增删页面注册；路由别名 `config/index.ts` 与 `src/router` 的 `ROUTE_ALIAS` 保持同步，禁止破坏 H5 别名映射）。
- 导航：一律 `routerNavigateTo(routeKey)` 等包装；带参跳转用新增的 `params` 参数（见 §10），**禁止页面内直调 Taro 导航 API**。
- 鉴权：登录页跳转/守卫统一 `useAuthGuard`/`requireAuth`（现状）。
- 三态齐全：loading（骨架/转圈）、空态（空文案）、错误态（错误信息 + 重试）；列表分页（上拉加载/触底）行为保持现状。
- 页面局部组件放 `pages/<Page>/components/`，同样遵守 §8 组件契约。
- 页面间"从详情返回列表"的软同步/滚动位置恢复等既有行为**必须保留**（Home 的 `softSyncFeed`、滚动位置记忆等）。
- 页面内常量（分类/排序/状态文案映射）移出组件体（模块级常量），稳定 `useCallback` 依赖。

## 10. 路由增强（src/router/index.ts，本轮实现）

- 保留现有导出：`ROUTE_PATHS / ROUTE_ALIAS / isAuthenticated / isPublicRoute / getCurrentPageFullPath / requiresAuth / routerNavigateTo / routerRedirectTo / routerSwitchTab / routerReLaunch / routerNavigateBack / goAfterLogin / goToLogin / requireAuth`。
- 为 `routerNavigateTo / routerRedirectTo / routerReLaunch` 增加可选第二参 `params?: Record<string, string | number>`：自动拼 query（`encodeURIComponent`），并**优先使用 H5 别名**（H5 下跳别名路径 + query，小程序下跳原路径）。
  ```ts
  routerNavigateTo('NOTE_DETAIL', { id: '123' })
  ```
- 页面现有对带参导航的实现方式（若有直调）由页面分片迁移到新签名；`ROUTE_ALIAS` 与 `config/index.ts` 的 `customRoutes` 键值必须逐一对齐（新增别名需两端同步——本轮不新增别名，只保证不破坏）。

## 11. 禁止事项清单（改前基线供对照）

1. `any` 滥用（基线 242 处 / 63 文件）——本轮目标归零或仅剩带注释的最小局部断言。
2. 页面/组件直调 `Taro.navigateTo/redirectTo/switchTab/reLaunch/request/uploadFile`（基线 60 处 / 27 文件）——一律收敛到 router/apis。
3. 渲染中 `setState`（render 内调用）。
4. 魔法字符串/数字散落（状态文案、分类映射等集中为模块级常量；token key 只在 `utils/token.ts` 出现）。
5. 列表缺 `key`。
6. store 内重复的解包样板（`if (res.code===0||res.code===200)`）——由 §7 统一写法消灭。
7. 死代码：未引用文件（死 .css 等）、未使用 import/变量（tsconfig 已开 noUnusedLocals，保持）。
8. 内联样式堆砌（仅动态值可内联）。
9. 命名不一致（中英混杂、`xxxAPI` 后缀残留、同义动词并存）。
10. 无关 `console.log` 调试噪音（保留有用 warn/error）。
11. 破坏 `.claude/worktrees` 下旧 worktree 目录、`.git` 结构。

## 12. 分片执行约定（对所有重构分片）

- **文件所有权**：每轮分片之间文件互不重叠；对他人文件的"最小同步修改"（改名/去 .data/类型导入调整）允许并须在报告中列出清单。
- **自检要求**：改完自己负责的文件后，运行 `pnpm exec tsc --noEmit`（若全仓有其他分片未完成的报错，先跑 `pnpm exec tsc --noEmit --pretty false 2>&1 | Select-String 'src/<自己领域>'` 过滤本领域错误），并自查 eslint（`pnpm exec eslint <文件列表>`）。
- **报告要求**：返回时附（1）改动文件绝对路径清单；（2）每个文件的关键改动点；（3）本领域内消灭的 any/直调导航/死代码数量；（4）遗留问题与理由（如需保留的局部断言）。
- 未经许可不得删除文件；确需删除（仅死 .css）由清理分片统一执行。
- 不新增页面、不改 `app.config.ts` 页面注册、不改 `config/index.ts` 的 customRoutes 映射、不触碰 `.claude/` 与 `.git/`。
